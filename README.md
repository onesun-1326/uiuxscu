## 9주차 : 폼 UI와 입력 경험

### 이번 주에 추가·수정한 기능
- 입력 칸(이름, Email, Message)마다 도움말을 넣고 `aria-describedby`로 입력 칸에 연결했다.
- 입력하는 동안 글자 수(`N / 10자`, `N / 500자`)와 조건 충족 여부(`✓ 입력 조건을 충족했습니다.` + 초록 테두리)를 표시한다.
- 오류 문구가 떠 있는 칸은 입력하는 동안 다시 검사해서, 올바르게 고치면 바로 오류가 해제된다.
- 2단계에 'SNS로도 답변받기' 체크박스를 추가했다. 체크하면 SNS 입력 칸이 나타나고, 해제하면 사라진다. (숨겨진 동안 `disabled`)
- 제출하면 '저장 중…'(버튼 잠금)을 거쳐 완료 화면이 뜨고, 저장에 실패하면 입력 내용을 유지한 채 '다시 시도'할 수 있다.
- 제출 직전에 1·2단계를 한 번 더 검사한다.
- 수정 : 완료 문구 앞에 '문의 내용이 이 브라우저에 저장되었습니다.'를 추가했다. 서버로는 보내지 않고 브라우저 localStorage(`seonwon-inquiry-sent`)에 최근 5건까지 저장한다.

### 입력 조건
| 칸 | 조건 | 도움말 | 오류 문구 (문제 + 고치는 방법) |
|---|---|---|---|
| 이름 | 필수, 공백 제외 1자 이상, 최대 10자 | 답변할 때 부를 이름입니다. 최대 10자까지 쓸 수 있습니다. | 이름을 입력해 주세요. 답변할 때 부를 이름입니다. |
| Email | 필수, `a@b.c` 형식 | 답변을 받을 주소입니다. 예: name@example.com | 비었을 때 : 이메일을 입력해 주세요. 답변을 받을 주소입니다. / 형식 오류 : 이메일 형식이 올바르지 않습니다. 예: name@example.com |
| Message | 필수, 공백 제외 10자 이상, 최대 500자 | 원하는 작업과 일정을 10자 이상 적어주세요. | 비었을 때 : 문의 내용을 입력해 주세요. 원하는 작업과 일정을 적어주시면 좋습니다. / 짧을 때 : 문의 내용이 너무 짧습니다. 10자 이상 적어주세요. (현재 N자) |
| SNS (체크했을 때만) | 필수, 공백 제외 2자 이상, 최대 50자 | 답변받을 SNS 아이디나 링크를 적어주세요. 예: @sunone.art | 비었을 때 : SNS 아이디나 링크를 입력해 주세요. 예: @sunone.art / 짧을 때 : SNS 아이디가 너무 짧습니다. 2자 이상 입력해 주세요. |

### 인터렉션 시나리오
- 행동 > 이벤트 > 조건 > 반응 > 다음 상태
    * 글자 입력     > input  > 2단계에서       > 글자 수·안내 문구 갱신, 조건 충족 시 '✓' 문구와 초록 테두리 > 오류가 떠 있던 칸은 바로 재검사
    * SNS 체크·해제 > change > 2단계에서       > SNS 입력 칸 표시·숨김, 숨기면 disabled                     > 해제하면 SNS 검사에서 제외
    * 제출 클릭     > submit > 3단계, 검사 통과 > '저장 중…', 제출 버튼 잠금, 이전·수정 버튼 잠금          > 저장 성공 시 4단계
    * 제출 클릭     > submit > 3단계, 검사 실패 > 제출하지 않고 해당 단계를 열어 오류 안내, 첫 오류 칸에 focus > 해당 단계 유지
    * 저장 실패     > 저장 중 > setItem 예외    > 3단계 유지, 입력값 유지, 버튼 '다시 시도', 실패 안내       > '다시 시도' 클릭 시 다시 저장
    * 새 문의 작성  > click  > 4단계에서       > 입력값·SNS 영역·안내 문구·글자 수·버튼 상태 초기화          > step = 1

### 실패 처리 (조건과 코드 위치)
- 저장 방식 : 제출 내용을 `localStorage`의 `seonwon-inquiry-sent` 키에 저장한다. (서버 연동 없음)
- 실패 조건 : `localStorage.setItem`이 예외를 던질 때. (저장 공간이 가득 찼거나 브라우저가 저장을 막은 경우)
- 코드 위치 : `script.js`의 `saveInquiry()` 안 `catch` → `setSubmitState("failed")`. 입력값(`inquiry`와 입력 칸)은 건드리지 않아 그대로 남는다.
- '저장 중…'이 눈에 보이도록 `submitDelay`(0.8초) 뒤에 저장한다.
- 시험 방법 : 개발자 도구 Console에서 `Storage.prototype.setItem = function () { throw new Error("quota"); }`로 실패를 만든 뒤 제출했다. 복구는 미리 `window.orig = Storage.prototype.setItem;`에 보관해 두었다가 되돌린다.

### 확인 순서
1. 2단계에서 입력 없이 이름 칸에서 Enter (빈 값 제출)
2. 이메일에 `abc`, 문의 내용에 `짧은글` 입력 (잘못된 값)
3. 올바르게 고쳐 오류가 해제되는지 확인 (오류 수정)
4. SNS 체크 → 비운 채 다음 → 1글자 입력 → 해제 → 다시 체크 (조건부 영역 변경)
5. 3단계 확인 후 제출 → 4단계 (정상 제출)
6. 저장 실패를 만들어 제출 → '다시 시도' (실패 처리)
7. '새 문의 작성'으로 초기화 확인
