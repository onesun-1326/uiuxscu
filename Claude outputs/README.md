### 직접 확인 순서 (키보드만 사용)
1. 새로고침 후 Tab을 눌러 다크 모드 버튼 → 메뉴 5개 → 탭 → 작업물 필터 → 카드 순서로 초점 윤곽선이 보이는지 확인한다.
2. 작업 분야 탭에서 ← → Home End로 탭이 바뀌는지 확인한다.
3. 작업물 필터 버튼을 Enter로 눌러 카드 수와 안내 문구가 바뀌는지 확인한다.
4. 카드에서 Enter → 창 안으로 초점 이동 → Esc → 같은 카드로 복귀하는지 확인한다.
5. 문의하기에서 일부러 빈 칸으로 '다음'을 눌러 오류 문구(⚠)와 첫 오류 칸 초점을 확인한다.
6. 다크 모드로 바꿔 버튼 글씨와 입력 칸 테두리가 또렷한지 확인한다.

## 10강 : 메뉴 이동과 목록 탐색

### 이번 주에 추가·수정한 기능
- 맨 위 메뉴를 `nav` + `ul·li` 구조로 바꾸고 이름을 5개로 정리했다. (소개 / 작업 분야 / 작업물 / 문의하기 / 내 문의)
- 지금 보고 있는 구역의 메뉴에 굵은 글씨 + 밑줄 + 진한 색을 주고 `aria-current="page"`를 붙인다. 다른 메뉴에서는 속성을 뺀다. 메뉴 클릭, 스크롤, 새로고침, 브라우저 뒤로 가기 모두 실제 화면 위치를 기준으로 다시 계산한다.
- 새 구역 '내 문의 내역'을 만들었다. 문의하기에서 제출한 내용(localStorage `seonwon-inquiry-sent`)을 최신순 목록으로 보여 주고, 유형별 필터 버튼 4개(전체 / 협업 문의 / 작업 문의 / 기타)와 건수 안내를 붙였다. 선택한 버튼은 `aria-pressed="true"`이고 글씨·테두리·밑줄도 달라진다.
- 결과가 없는 두 경우를 구분해서 안내한다. (아래 표 참고)
- 모바일(768px 이하)에서는 메뉴를 '메뉴 열기 / 메뉴 닫기' 버튼으로 접고 편다. 화면 문구, 버튼 글자, `aria-expanded`가 함께 바뀌고, 메뉴를 고르면 해당 구역으로 이동하면서 메뉴가 닫힌다. Esc로도 닫힌다.
- 4단계(완료 화면)에 '내 문의 내역 보기' 링크를 추가했다.
- 기존 기능(문의 입력 4단계, 저장, 작업물 상세 창)은 그대로 동작한다. (작업물 분야 필터는 11강에서 체크박스를 버튼 + `aria-pressed`로 바꿨다.)

### 메뉴 이동 위치
| 메뉴 이름 | 이동하는 곳 (`id`) | 내용 |
|---|---|---|
| 소개 | `#about` | 프로필과 소개 글 |
| 작업 분야 | `#fields` | 3D 그래픽 / 2D 일러스트 / AI 영상 탭 |
| 작업물 | `#works` | 작업물 목록과 분야 필터 |
| 문의하기 | `#contact` | 4단계 문의 폼 |
| 내 문의 | `#history` | 내가 보낸 문의 목록과 유형 필터 |

### 필터 기준 ('내 문의 내역')
| 버튼 | 보여 주는 문의 | 기준 값 |
|---|---|---|
| 전체 | 저장된 문의 전부 | - |
| 협업 문의 | 문의 유형이 '협업 문의'인 것 | `type === "collab"` |
| 작업 문의 | 문의 유형이 '작업 문의'인 것 | `type === "work"` |
| 기타 | 문의 유형이 '기타'인 것 | `type === "etc"` |

목록은 항상 최신순이고, 한 건마다 유형·제출 시각·관심 분야·(있으면) 관련 작업·문의 내용 앞부분(60자까지)을 보여 준다. 이메일과 이름은 목록에 표시하지 않는다.

| 상황 | 건수 안내 (`role="status"`) | 목록 자리 안내 | 보이는 버튼 |
|---|---|---|---|
| 저장된 문의가 하나도 없음 | 저장된 문의가 없습니다. | 아직 보낸 문의가 없어요. 문의하기에서 첫 문의를 남겨 보세요. | '문의 남기러 가기' 링크 |
| 문의는 있지만 고른 유형에 해당하는 것이 없음 | '기타' 문의는 0건입니다. (전체 3건) | '기타' 유형으로 보낸 문의가 없어요. 다른 유형을 고르거나 전체를 확인해 보세요. | '전체 보기' 버튼 |

## 9주차 : 폼 UI와 입력 경험

### 이번 주에 추가·수정한 기능
- 입력 칸(이름, Email, Message)마다 도움말을 넣고 `aria-describedby`로 입력 칸에 연결했다.
- 입력하는 동안 글자 수(`N / 10자`, `N / 500자`)와 조건 충족 여부(`✓ 입력 조건을 충족했습니다.` + 초록 테두리)를 표시한다.
- 오류 문구가 떠 있는 칸은 입력하는 동안 다시 검사해서, 올바르게 고치면 바로 오류가 해제된다.
- 2단계에 'SNS로도 답변받기' 체크박스를 추가했다. 체크하면 SNS 입력 칸이 나타나고, 해제하면 사라진다. (숨겨진 동안 `disabled`)
- 제출하면 '저장 중…'(버튼 잠금)을 거쳐 완료 화면이 뜨고, 저장에 실패하면 입력 내용을 유지한 채 '다시 시도'할 수 있다.
- 제출 직전에 1·2단계를 한 번 더 검사한다.
- 수정 : 완료 문구 앞에 '문의 내용이 이 브라우저에 저장되었습니다.'를 추가했다. 서버로는 보내지 않고 브라우저 localStorage(`seonwon-inquiry-sent`)에 저장한다. (10강에서 '내 문의 내역'을 만들면서 보관 건수를 5건 → 20건으로 늘렸다.)

### 입력 조건

|---|---|---|---|

### 인터렉션 시나리오
- 행동 > 이벤트 > 조건 > 반응 > 다음 상태
    * 글자 입력     > input  > 2단계에서       > 글자 수·안내 문구 갱신, 조건 충족 시 '✓' 문구와 초록 테두리 > 오류가 떠 있던 칸은 바로 재검사
    * SNS 체크·해제 > change > 2단계에서       > SNS 입력 칸 표시·숨김, 숨기면 disabled                     > 해제하면 SNS 검사에서 제외
    * 제출 클릭     > submit > 3단계, 검사 통과 > '저장 중…', 제출 버튼 잠금, 이전·수정 버튼 잠금          > 저장 성공 시 4단계
    * 제출 클릭     > submit > 3단계, 검사 실패 > 제출하지 않고 해당 단계를 열어 오류 안내, 첫 오류 칸에 focus > 해당 단계 유지
    * 저장 실패     > 저장 중 > setItem 예외    > 3단계 유지, 입력값 유지, 버튼 '다시 시도', 실패 안내       > '다시 시도' 클릭 시 다시 저장
    * 새 문의 작성  > click  > 4단계에서       > 입력값·SNS 영역·안내 문구·글자 수·버튼 상태 초기화          > step = 1

### 실패 처리 (조건과 코드 위치)
- 저장 방식 : 제출 내용을 `localStorage`의 `seonwon-inquiry-sent` 키에 저장한다. (서버 연동 없음)
- 실패 조건 : `localStorage.setItem`이 예외를 던질 때. (저장 공간이 가득 찼거나 브라우저가 저장을 막은 경우)
- 코드 위치 : `script.js`의 `saveInquiry()` 안 `catch` → `setSubmitState("failed")`. 입력값(`inquiry`와 입력 칸)은 건드리지 않아 그대로 남는다.
- '저장 중…'이 눈에 보이도록 `submitDelay`(0.8초) 뒤에 저장한다.
- 시험 방법 : 개발자 도구 Console에서 `Storage.prototype.setItem = function () { throw new Error("quota"); }`로 실패를 만든 뒤 제출했다. 복구는 미리 `window.orig = Storage.prototype.setItem;`에 보관해 두었다가 되돌린다.

### 확인 순서
1. 2단계에서 입력 없이 이름 칸에서 Enter (빈 값 제출)
2. 이메일에 `abc`, 문의 내용에 `짧은글` 입력 (잘못된 값)
3. 올바르게 고쳐 오류가 해제되는지 확인 (오류 수정)
4. SNS 체크 → 비운 채 다음 → 1글자 입력 → 해제 → 다시 체크 (조건부 영역 변경)
5. 3단계 확인 후 제출 → 4단계 (정상 제출)
6. 저장 실패를 만들어 제출 → '다시 시도' (실패 처리)
7. '새 문의 작성'으로 초기화 확인
